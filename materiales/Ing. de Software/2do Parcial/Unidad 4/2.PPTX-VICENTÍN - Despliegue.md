Durante la clase se menciono que podemos tener nuestro cliente-servidor y que podemos tener nuestra infra en donde se nos cante (en el ejemplo son sv enterprise) pero tmb se dieron otros ejemplos; y que pueden ser sv fisicos, vms, contneedores, cloud o baas lo q sea.
En definitiva, también necesitaremos distintos ambientes.
![[Pasted image 20251126020012.png]]

Todos dependen de la necesidad de la empresa, pero generalmente siempre se tiene.
- Ambiente de desarrollo (Tal vez suele ser la maquina local de los programadores)
- Ambiente de prueba (testing -> Para probar)
- Ambiente de producción (La que usan los clientes directos)
- Los ambientes de pre-producción a veces no existen; ya que son muy costosos de mantener.

Vicentín explico el concepto de infra:
- Server fisicos normales de toda la vida > Vas a necesitar tener la infra para mantenerlo, una persona q los mantenga, condiciones, etc etc 
- Maquinas virtuales de toda la vida; necesitas de vuelta mucha infra y a veces medio al pedo
- Contenedores: tienen un engine que te sirve para aislar las funciones basicas de un kernel de un so y ese engine lo podes usar para correr el resto de contenedores; asi directamente no tengas que levantar una mv para usarlo. Basicamente son una tecnología que permite empaquetar y ejecutar aplicaciones de manera aislada, ligera y portatil dentro de un so; es una cajita que incluye todo lo necesario para que tu app funcione.

## Docker
Es una plataforma de contenedores que permite empaquetar una aplicación junto con todas sus dependencias, librerías y configuraciones, en una unidad estándar llamada contenedor.
Cada contenedor puede ejecutarse en cualquier entorno que tenga docker instalado, sin importar el SO; garantizando consistencia y portabilidad.

## Kubernetes
K8S es una plataforma de orquestación que automatiza el despliegue, escalado y gestión de contenedores en entornos distribuidos (clusters); creada por google y hoy un estandar. Ejecuta, monitorea y mantiene disponible los contenedores de una aplicación, a través de muchos servidores.

## Cultura de CI/CD
No se limita a un conjunto de herramientas, sino a la forma de trabajar y pensar en equipo dentro del desarrollo de software; integrando prácticas técnicas con valores organizacionales que fomenten la colaboración, la calidad y la entrega rápida de valor.
![[Pasted image 20251126020846.png]]
La idea es que tienda a ser infinita básicamente y se siga utilizando constantemente.
Es una mentalidad que combina automatización, colaboración y mejora continua, permitiendo entregar software de calidad más rápido y con menos riesgos.

### Integración continua (CI)
Es el proceso de construir y probar código automáticamente cada vez que se confirman los cambios en un sistema de control de versiones (Cuando hay un PR). Un request de merge; activa esta solicitud para construir, probar y validar la rama completa. Anima a los desarrolladores a compartir sus pruebas de código y unidad fusionando sus cambios en el repo, cada vez que se completa una tarea.
CI hace que los test que estaban antes se vuelvan a ejecutar, para verificar que no se rompa nada.

### Entrega Continua (CD)
Es una práctica del desarrollo de software mediante la cual se compilan, prueban y preparan automáticamente los cambios en el código y se entregan a producción. Amplia la CI implementado todos los cambios en el código en un entorno de prueba o producción automáticamente.
